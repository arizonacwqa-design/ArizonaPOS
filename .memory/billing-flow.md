# Billing Flow (POS)

## Overview
The POS billing system lives in `src/pages/POS.jsx` with supporting logic in `src/lib/pos.js`. It follows a 4-step workflow:

## Step-by-Step Flow

### Step 1 — Customer & Vehicle Info
- **Component**: `CustomerAutocomplete` (searches existing customers by name/phone)
- User enters: customer name (required), phone, car model, car plate, optional notes
- On sale completion, customer is upserted into `customers` table

### Step 2 — Select Services
- Services fetched from Supabase `services` table (active only, with inventory_item join)
- Filterable by category (PPF, Tint, Coating, Detailing, Polish) and search text
- Each service button shows: name, category, price, and linked inventory info
- Tapping a service adds it to cart via `cartLineFromService()`
- If service already in cart, quantity increments

### Step 3 — Inventory Usage (Optional Materials)
- **Component**: `InventoryUsageSection` in `src/components/pos/InventoryUsageSection.jsx`
- User can add materials (PPF rolls, tint rolls, chemicals) directly to cart
- Materials are non-revenue items (line_total = 0) but deduct stock
- Meter items increment by 0.5, quantity items by 1

### Step 4 — Cart & Checkout
- Cart displays all line items with quantity controls (+/-)
- Auto stock deduction preview shown in amber warning box
- Subtotal, discount (flat QAR or %), tax toggle/rate, payment method
- Grand total computed by `calcBillingTotals()`

### Complete Sale
1. **Validations**:
   - Customer name required, max 100 chars
   - Cart must have at least 1 item
   - `validateCartStock()` checks all inventory against current stock

2. **Customer upsert**: `upsertCustomerFromSale()` creates or updates customer record (by phone)

3. **Atomic sale creation**: `supabase.rpc('create_sale', { p_sale, p_items })`
   - Postgres function inserts sale + items in single transaction
   - `on_sale_item_inventory` trigger fires on each item:
     - Row-level lock (`SELECT ... FOR UPDATE`)
     - Validates sufficient stock
     - Deducts inventory
   - Fails entire transaction if stock insufficient

4. **On success**:
   - Cart cleared, customer reset
   - Invoice number displayed (e.g., `INV-1001`)
   - Post-sale actions available:
     - **Print Thermal** (80mm) — `window.print()` or `electronAPI.printInvoice()`
     - **Print A4** — Same mechanism, different CSS class
     - **Download PDF A4** — jsPDF + jspdf-autotable
     - **Download PDF Thermal** — jsPDF
     - **WhatsApp Customer** — prebuilt message with invoice details
     - **Share to Shop** — WhatsApp without recipient

## Discount Logic (`calcBillingTotals`)
```
subtotal > 0
  → discount (flat QAR or % of subtotal, capped at subtotal)
  → afterDiscount = subtotal - discount
  → tax = afterDiscount × (taxRate / 100)  [if taxEnabled]
  → total = afterDiscount + tax
```

## Invoice Numbering
- Auto-incrementing sequence: `invoice_number_seq` starts at 1001
- Format: `INV-{number}` (e.g., `INV-1001`)
- Generated by Postgres `DEFAULT` on `sales` table

## Inventory Deduction on Sale

Two paths for stock deduction:

1. **Service-linked inventory**: If a service has `inventory_item_id` and `consumption_per_unit > 0`, each sale of that service deducts `consumption_per_unit × quantity` from inventory.

2. **Direct material usage**: Items added as "material" lines in Step 3 deduct their quantity directly.

Both paths use the same trigger `on_sale_item_inventory` which fires `apply_sale_inventory_deduction()`.

## Invoice Formats

### Thermal (80mm)
- Width: 80mm, monospace font
- Logo, company info, customer, items, totals, QR code
- Hidden DOM element (#thermal-invoice), shown during print

### A4
- Full letter/A4 layout
- Light background with gold accents
- Logo, company header, "INVOICE" heading
- Items table, payment info, totals, notes

### PDF
- Generated client-side via jsPDF + jspdf-autotable
- Gold-accented header row
- Available in both A4 and thermal format
